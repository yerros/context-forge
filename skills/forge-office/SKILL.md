# forge-office

The plugin bundles a local web dashboard (`dashboard/` in the plugin root): a
kanban board parsed from `progress-tracker.md` + the build plan, live claims and
locks, an activity feed from the local metrics, and a 2D pixel office where the
nine forge agents visibly work (desks, meeting table, lounge).

Live interaction (0.37.0):

- **Per-agent live activity (0.50.0)** — every character carries a crisp label
  with what it is doing right now ("Reading auth.ts", "Running: npm test"):
  Claude from the `now-status.sh` PreToolUse hook, each subagent from its own
  transcript under `~/.claude/projects/<project>/<session>/subagents/`
  (read-only). Reading tools show a still pose, writing/running an animated
  one. Claude blocked on you gets a pixel bubble: amber "…" = needs approval,
  green ✓ = waiting for input (`wait-status.sh` on Notification /
  PermissionRequest / Stop). Presence dots on every name tag (green = working,
  yellow = break or waiting, gray = idle).
- **Chat** — the bar under the office (or clicking a character) sends a message
  that the `office-inbox.sh` UserPromptSubmit hook injects as context at the
  next Claude Code prompt in that project. Delivered exactly once.
- **Assign** — "▶ assign" on a Next Up card queues "build unit NN next" through
  the same inbox.

Project-safe by design — the dashboard NEVER writes to the project; chat and
assignments go to `~/.claude/forge-office/inbox/<project>.ndjson` only. It
binds to 127.0.0.1 only. Requires Node ≥ 18.

## Argument

- *(none)* or `start` → start for the current project and print the URL.
- `stop` → stop the server.
- `status` → running state, project, URL, autostart setting.
- `autostart on` / `autostart off` → start automatically at `SessionStart` in
  any Context Forge project (silent, one URL line when it starts fresh).

## Steps

1. Run the launcher with the requested action:

   ```bash
   bash "${CLAUDE_PLUGIN_ROOT}/skills/forge-office/scripts/forge-office.sh" <action>
   ```

   `start` is idempotent (an already-running server is reported, not duplicated)
   and verifies the server actually serves before reporting success. On macOS it
   opens the browser; otherwise relay the URL.
2. Relay the script's output verbatim — it contains the URL and, on failure,
   the log path (`~/.claude/forge-office/<port>.log`).
3. If the user asked for automatic behavior ("always run this"), use
   `autostart on` and mention it applies to every Context Forge project on this
   machine.

## Notes

- The sprite office: original sprite characters + brick wall with neon FORGE
  sign, central glass meeting room, oak parquet, zone rugs + sign badges,
  server rack, coffee bar, lounge, warm lighting — all original art
  (`dashboard/public/sprites.png`, generated by
  `dashboard/sprites/forge_sprites.py`; regenerate with Python3 + Pillow).
  Forge agents work at their own desks; visiting non-forge agents (Explore,
  general-purpose…) sit at the meeting table. (The old `?classic=1`
  procedural office was removed in 0.50.0.)
- Live card (0.50.0): the In Progress column shows one lane per live worker —
  Claude first, then every agent — with its current tool, fg/bg, run time;
  click a lane for that worker's own timeline of recent actions.
- Port: `$FORGE_OFFICE_PORT` (default 4820). One server per port; a second
  project needs a different port.
- The live agent presence and the activity feed come from the plugin's own
  hooks (agent-status, metrics — on by default since 0.29.0); no setup needed.
- Never expose the port publicly; for remote access recommend a private
  tailnet (Tailscale).
